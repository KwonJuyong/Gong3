# 협업 전 점검

기준일: 2026-11-11. 코드·로컬 실행 점검 결과이며 운영 서버의 안전성 보증이나 전체 기능 검수 완료를 의미하지 않음.

## 수정 사항

- 이미지·메시지·민감 첨부 업로드: 용량 헤더 대신 실제 본문 크기 제한, 초과 시 스트림 취소, 실제 수신량으로 일일 한도 집계
- 이미지·메시지 업로드: 파일 대신 문자열을 전송한 경우 400 응답
- 외부 서비스 표시 확인: IPv4 매핑 IPv6·내부 및 예약 주소 차단, DNS 조회와 연결 시 동일 검사 적용
- 외부 서비스 표시 확인: 잘못된 리다이렉트 처리, 호스트별 캐시 구분과 최대 크기 제한
- 개발 DB: 모든 인터페이스 공개에서 `127.0.0.1:5433`으로 제한
- CI: Node 24, 전체 `verify`, 프로덕션 빌드 적용. 읽기 전용 권한 및 중복 실행 취소
- 커밋 검사 훅과 보안 회귀 테스트 포함, Windows 실행·검증 안내 보완
- Prisma 6.19.3·OpenAI SDK 7.55.0 및 하위 의존성 보안 패치 적용. Node 24 기준 검증

API 점검은 로컬 서버를 먼저 실행한 뒤 별도 터미널에서 실행:

```bash
npm run start -- --hostname 127.0.0.1 --port 3100
npm run test:api
```

`test:api` 기본 주소는 `http://127.0.0.1:3100`, 변경은 `TEST_BASE_URL` 환경변수. 로그인·권한별 허용 요청 검증은 별도 필요.

## 기능 확인 순서

1. 로컬 개발 DB 생성, 마이그레이션·기본 시드 실행
2. 학생·개설자·관리자 로그인, 로그아웃, 비밀번호 변경 및 기존 세션 차단
3. 서비스 등록 → 평가 생성 → 관리자 승인 → 모집·선발 → 응답 제출·수정 → 결과 내보내기
4. 마지막 자리 동시 제출, 같은 계정의 중복 제출, 저장 중 DB 오류
5. 이미지·메시지·민감 첨부 업로드와 다른 계정에서의 접근 제한
6. 가짜 데이터로 의뢰·보상 생성·검수·지급 상태 확인, 중복 처리 방지
7. 모바일·데스크톱 화면 캡처와 PR 첨부

- 운영 DB·실제 학생 개인정보 사용 금지
- 메일·팝빌·LLM 연동은 별도 테스트 설정 필요. 실제 발송·세금계산서 발행은 위 로컬 검사에 포함되지 않음
- 공개 제외된 검증도구 문항 시드·국세청 엑셀 양식은 이 저장소만으로 재현 불가
- 코드 구조상 `DashboardView.tsx`의 2천 줄 이상 파일, 사용자 전체 행 조회, 목록 상한 등 추가 정리 필요. 화면 작업은 담당 영역별 분리 권장
- 주소 검증 참고: [OWASP SSRF 예방 지침](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
